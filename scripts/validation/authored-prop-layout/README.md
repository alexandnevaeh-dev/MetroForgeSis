# Native authored-prop integration regression

Copy the current godot-topdown-adventure template into an isolated E: test directory, then copy these two files into its root. Run Godot 4.6 headlessly against res://integration-check.tscn under that project. Use the normal scene path rather than --script: the real manager depends on normal autoload initialization. Redirect temporary/cache/user data to E: using the project's established validation environment.

The scene writes integration-result.json and exits nonzero on failed assertions. A deliberately invalid authored scale produces one expected warning. The checks cover unchanged legacy position/anchor/footprint, authored position/scale/two footprints, and rejection without unsafe fallback. They do not validate desktop IPC, generation placement, under-arch occlusion or final artwork.

## Editor-to-runtime doorway check
The editor-runtime-check scene consumes editor-saved-overworld.json copied unchanged from the desktop test project, plus its assets directory. Run in an isolated copy of the current top-down template after import. It checks one gateway at its saved coordinates, 23 baked layers and two collision shapes, renders a screenshot and writes result.json. This fixture expects the existing development doorway pack; it is not a generic generated-game or character collision test. Keep all outputs on E:.

Terrain parity: terrain-parity.tscn calls the current OverworldManager selector for 25,600 cells across four area IDs and writes terrain-role-native.json. Compare these records with the desktop topdown-terrain.ts resolver. This covers terrain role choice, not rendered atlas pixels or absent-role combinations.

Player terrain check: provide painted-test.json and erased-test.json generated by saveTopDownTerrain for a 12x8 room (16px cells), with a full wall column at x=6 and then all dirt. The native scene instantiates the actual Player.tscn, sends move_right for 90 physics frames and checks blocking versus passage. Requires the template autoloads and player artwork for normal animation initialization. It is headless movement evidence, not visual approval.

Directional animation check: copy directional-animation-check.gd into an isolated current top-down template and run --headless --script res://directional-animation-check.gd --quit-after 120. Requires DIRECTIONAL_STRIPS_AND_PHASE_PASS, not exit code alone. Creates synthetic texture resources only in that isolated project/user directory. Covers independently sized horizontal strips, invalid-width rejection, derived directional idle, fallback, no mirroring of authored directions, preserved normalized walk phase and locked attack facing. It does not validate generated artwork or full-body fluidity.

Attack-facing check: run attack-facing-check.tscn in the isolated current template. Actual Player.tscn starts left, turns right during startup and verifies the first hitbox remains left while the next attack points right. Requires printed passed:true, not just timeout exit0. A missing attack.wav warning in the minimal fixture does not validate audio.

Attack collision check: run attack-collision-check.tscn under an isolated current template with native Godot. It instantiates Player.tscn and real HurtboxComponent targets, exercises actual physics area events in eight directions, and requires one front hit, zero rear hits and no second hit after same-swing exit/reentry. Read attack-collision-result.json passed:true and all eight results. This does not validate enemy health, animation timing, audio or visual quality.
